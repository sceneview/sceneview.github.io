probeARMotionSensors

suspend fun probeARMotionSensors(context: Context, windowMillis: Long = AR_MOTION_SENSOR_PROBE_WINDOW_MS): ARMotionSensorSample?

Listens to the gyroscope and the accelerometer for windowMillis and returns how many events each delivered, or null when the phone has no gyroscope or no accelerometer (such a phone is not ARCore-supported in the first place).

Call it when an AR session has been delivering camera frames for a while — some ten seconds — without ever tracking and without a TrackingFailureReason; read ARMotionSensorSample.health and, on ARMotionSensorHealth.SILENT, tell the person to restart their phone. SceneView draws nothing for it and reports no session failure: ARCore itself reports none.

Wait and listen in the foreground only — a paused session is not a stalled one, and a backgrounded app is delivered no sensor event:

val lifecycle = LocalLifecycleOwner.current.lifecycle
LaunchedEffect(neverTracked, lifecycle) {
    if (!neverTracked) return@LaunchedEffect
    lifecycle.repeatOnLifecycle(Lifecycle.State.RESUMED) {
        delay(10_000)
        val sample = probeARMotionSensors(context) ?: return@repeatOnLifecycle
        restartPhoneCard = sample.health == ARMotionSensorHealth.SILENT
    }
}

Both listeners are unregistered when the window ends, and when the calling coroutine is cancelled: no sensor registration outlives the call. Do not run it while tracking works — it has nothing to say then.

When the sensor service refuses either registration, nothing is listened to and the sample comes back at once with a negative count for the refused sensor: its health is ARMotionSensorHealth.UNKNOWN, never ARMotionSensorHealth.SILENT — a gyroscope that was not listened to has not been heard silent.

Parameters

context

any context; its application context is used.

windowMillis

how long to listen, one second by default. Shorter than 500 ms can only ever yield ARMotionSensorHealth.UNKNOWN or ARMotionSensorHealth.DELIVERING.
