RerunBridge

class RerunBridge @JvmOverloads constructor(host: String = DEFAULT_HOST, port: Int = DEFAULT_PORT, rateHz: Int = DEFAULT_RATE_HZ, tag: String = "RerunBridge")

Streams ARCore session data to a Rerun viewer over TCP using the JSON-lines wire format defined by RerunWireFormat.

Why this exists

Rerun has no native Kotlin SDK. The bridge emits one JSON object per line and a tiny Python sidecar (tools/rerun-bridge.py, generated by the rerun-3d-mcp package) reads the socket and re-logs each event into the Rerun viewer as the matching archetype (Transform3D, Points3D, LineStrips3D, …). The developer runs the sidecar + rerun on their dev machine, then adb reverse tcp:9876 tcp:9876 and launches the app.

Threading

All I/O runs on Dispatchers.IO via a dedicated supervisor scope. The public log* methods are non-blocking: each event is enqueued on a rendezvous Channel with CONFLATED behaviour so the newest event wins and backpressure drops frames silently. This is the only correct choice for a render-loop callback — Filament's main-thread contract forbids blocking inside onSessionUpdated.

That queue belongs to the connection, not to the bridge: connect installs a fresh one, so events logged while disconnected are dropped rather than replayed onto the next connection. See connect.

Usage

Prefer the composable rememberRerunBridge helper; this class is public so non-Compose hosts (plain Views, unit tests) can still use it.

val bridge = RerunBridge(host = "127.0.0.1", port = 9876, rateHz = 10)
bridge.connect()
try {
    arSession.onFrame { frame -> bridge.logFrame(session, frame) }
} finally {
    bridge.disconnect()
}

Parameters

host

Host to connect to. Use 127.0.0.1 with adb reverse tcp:$port tcp:$port.

port

TCP port the Python sidecar listens on.

rateHz

Maximum number of frames logged per second. Later events are dropped. Default: 10 Hz. Set to 0 to disable throttling.

tag

Logcat tag used for connection errors.
