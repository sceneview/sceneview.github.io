DimensionMarks

@Composable
fun SceneScope.DimensionMarks(size: Size, format: (metres: Float) -> String, labels: Size = size, lineColor: Color = Color.White, labelText: Color = Color.White, labelBackground: Color = DimensionMarksDefaults.LabelBackground, selectable: Boolean = false, labelScale: Float = 1.0f, facing: () -> Position? = null, heightOffset: Float = 0.0f, heightTagSide: Direction? = null, clearance: DimensionTagClearance? = null)

Dimension lines around a box of size metres standing at the origin (bottom at y = 0, centred on X and Z), with their values written next to them: width along the front (+Z), depth along the right side (+X), height up the right-front corner. The marks are drawn at the box's real size, outside any node that stretches the object, so the text never deforms. Unlit: they cast and receive no shadow (#5209).

In AR, pass facing so the tags turn to the camera instead of reading backwards from behind, and clearance so a tag hides while it is under the app's controls. With AutoPlacementState.guide, show them when guide.dimensions is true; an app whose answer is the size (a furniture fit) may keep them on.

Declared inside an AutoPlacementNode's content, the marks follow the object and scale with a pinch, so pair them with allowsScaling = false (real-size furniture), as here.

AutoPlacementNode(placement, state, size = Size(0.9f, 0.85f, 0.6f)) { opacity ->
    Sofa(opacity)
    if (state.guide.dimensions) DimensionMarks(
        size = Size(0.9f, 0.85f, 0.6f),
        format = { metres -> "${(metres * 100).roundToInt()} cm" },
        facing = { cameraPosition },
    )
}

Parameters

format

writes one length, in metres.

labels

the lengths the tags write; defaults to size. A view that animates size with an overshooting spring passes the target here, so the tags never read 91 cm on the way to 90.

selectable

lines and tags take taps for the object they measure, as its own body does.

labelScale

1 for a 34 cm tag (AR); a 3D view of a large object passes more.

facing

where the camera is, for the tags to turn to it; null keeps them facing +Z.

heightOffset

how much further right the height line stands than the floor lines, so it never runs up an armrest in a 3D view; AR keeps it on the corner.

heightTagSide

the screen's right, flat on the floor: given, the height tag starts at its line and runs right, off the object behind it; null keeps it centred on top.

clearance

where the app's chrome is on screen, for the tags to keep out from under it.
