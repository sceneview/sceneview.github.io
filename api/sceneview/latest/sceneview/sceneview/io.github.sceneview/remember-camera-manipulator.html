rememberCameraManipulator

@Composable
fun rememberCameraManipulator(orbitRadius: Float, targetPosition: Position? = null, inertia: Inertia = Inertia.Default, key: Any? = null, creator: () -> CameraGestureDetector.CameraManipulator = { createDefaultCameraManipulator(orbitRadius = orbitRadius, targetPosition = targetPosition) }): CameraGestureDetector.CameraManipulator

Creates and remembers a CameraGestureDetector.CameraManipulator whose camera starts orbitRadius metres from targetPosition, along io.github.sceneview.gesture.DEFAULT_ORBIT_DIRECTION — the same gentle 3/4 angle as the default CameraNode, so orbitRadius = 2.78f reproduces the stock framing.

This is the distance-first spelling of rememberCameraManipulator (it mirrors the iOS CameraControls.orbitRadius). Under the default autoCenterContent = true the subject sits on the origin, so with the default target orbitRadius is exactly the camera-to-subject distance — no vector length to compute. See io.github.sceneview.gesture.orbitEyePosition for the derivation.

    cameraManipulator = rememberCameraManipulator(orbitRadius = 3f),
) { ModelNode(modelInstance) }

Changing the radius or the target

The manipulator is keyed on orbitRadius, targetPosition and key: pass a new value (a radius derived from a model's measured size, a target that moves once the model has loaded) and a fresh manipulator frames it. SceneView glides the camera from the pose on screen to the new framing over ~0.6 s instead of cutting. A rebuild starts a new orbit, so the user's current orbit angle is replaced by the default 3/4 view: derive the radius once from what it depends on, don't animate it frame by frame.

creator is not a key (a lambda that captures a value re-created on recomposition is a new instance every time): a different creator is used at the next rebuild — change key to make that happen now.

Going back to the start

Change key to rebuild the manipulator at its starting framing; the camera glides back. A "double-tap to reset the view", with no key { } block around the call:

var resets by remember { mutableIntStateOf(0) }
SceneView(
    cameraManipulator = rememberCameraManipulator(orbitRadius = 3f, key = resets),
    onGestureListener = rememberOnGestureListener(onDoubleTap = { _, _ -> resets++ }),
)

Inertia

A flick keeps the camera turning (or panning, or zooming) after the finger lifts, then slows down to a stop — Inertia.Default. Pass inertia = Inertia.None for a camera that stops dead on release. Changing it does not rebuild the manipulator.

Parameters

orbitRadius

Camera-to-target distance in metres. Must be > 0.

targetPosition

Point in world space the camera orbits around and initially looks at (optional; defaults to the origin).

inertia

How orbit, pan and pinch coast after release. Applied to the manipulator creator returns when it is a CameraGestureDetector.DefaultCameraManipulator. Never rebuilds it.

key

Any value, like the key of remember(key) { }: when it changes, the manipulator is rebuilt by creator at its starting framing and the camera glides back there. null (the default) never triggers a rebuild on its own.

creator

Factory for the manipulator. Override to set a custom orbit speed, etc. Called again whenever orbitRadius, targetPosition or key changes — not when only the lambda instance changes.

@Composable
fun rememberCameraManipulator(orbitHomePosition: Position? = null, targetPosition: Position? = null, inertia: Inertia = Inertia.Default, key: Any? = null, creator: () -> CameraGestureDetector.CameraManipulator = { createDefaultCameraManipulator(orbitHomePosition, targetPosition) }): CameraGestureDetector.CameraManipulator

Creates and remembers a CameraGestureDetector.CameraManipulator for orbit/pan/zoom control.

The manipulator translates touch gestures into camera transform updates — one-finger drag to orbit, two-finger drag to pan, pinch to zoom. It is updated automatically every frame inside SceneView.

Pass null to SceneView(cameraManipulator = null) to disable camera interaction entirely.

orbitHomePosition is the camera's eye position — not a "home" it returns to on its own: no built-in gesture does that, the built-in double-tap zooms in (see "Going back to the start" below for the one-line way to reset). For the common case of framing a subject from a known distance, prefer rememberCameraManipulator with orbitRadius instead — it sidesteps the vector-length reasoning below entirely.

val cameraManipulator = rememberCameraManipulator(
    // Eye 2.5 m from an auto-centred subject — it is the LENGTH of this vector that frames.
    orbitHomePosition = Position(x = 0f, y = 0.5f, z = 2.45f),
    targetPosition    = Position(x = 0f, y = 0f, z = 0f)
)

How far away the camera actually ends up

orbitHomePosition is the eye's absolute world position: Filament's OrbitManipulator assigns it verbatim (mEye = mProps.orbitHomePosition, defaulting to (0, 0, 1)) and never re-bases it on targetPosition. targetPosition sets the orbit pivot and the direction the camera initially looks in — it does not set the distance.

What makes that easy to get wrong is the interaction with auto-centring. Under SceneView's default autoCenterContent = true the DSL content is translated so its bounding-box centre lands on the world origin, so the distance your subject is framed from is |orbitHomePosition| — the coordinates you gave your nodes do not survive, and targetPosition does not enter into it:

// Nodes authored at z = -1.5 are auto-centred back onto the origin, so this frames the
// subject from |(0, 0.2, 1.2)| ≈ 1.22 m — NOT from |(0, 0.2, 1.2) − (0, 0, -1.5)| ≈ 2.7 m.
rememberCameraManipulator(
    orbitHomePosition = Position(0f, 0.2f, 1.2f),
    targetPosition    = Position(0f, 0f, -1.5f)
)

Aiming targetPosition at where the content was authored does not push the subject away from the camera; it only tilts the view. Both readings coincide whenever the target is the origin, which is why every doc example looks fine and why this cost issue #2873 its diagnosis (the demo was framed from 1.22 m while its own comment claimed 2.7 m). Pass autoCenterContent = false to SceneView when authored world positions should survive; the framing distance is then |orbitHomePosition − contentCentre|. The orbitRadius overload sidesteps all of this for the common case: with the default (origin) target its value is the subject distance (#2932).

Changing the inputs

The manipulator is keyed on orbitHomePosition, targetPosition and key, compared by value: pass a new eye or target (a framing computed once the model has loaded, a viewpoint picker) and a fresh manipulator is built from it, and SceneView glides the camera from the pose on screen to the new one over ~0.6 s instead of cutting. Passing an equal value again — a Position(…) literal re-created on every recomposition — changes nothing. A rebuild starts a new orbit, so whatever the user did to the camera is replaced: derive the eye once from what it depends on, don't animate it frame by frame.

Never pass a live value such as cameraNode.worldPosition: the camera node follows the manipulator, so that value changes on every orbit and each recomposition would rebuild the manipulator under the user's finger. To start from the camera node's position, leave the cameraManipulator argument out — SceneView's default does exactly that, without rebuilding.

creator is not a key: a lambda is a new instance whenever it captures a value that is re-created on recomposition, which would rebuild the camera on every recomposition. A different creator is picked up the next time the manipulator is rebuilt — change key to make that happen now. inertia never rebuilds: it is written onto the live manipulator.

Going back to the start

Change key to rebuild the manipulator at its starting pose: SceneView glides the camera back over ~0.6 s. The classic "double-tap to reset the view", with no key { } block around the call — the built-in double-tap zoom is turned off so it does not start before the glide:

var resets by remember { mutableIntStateOf(0) }
SceneView(
    cameraManipulator = rememberCameraManipulator(
        orbitHomePosition = Position(x = 0f, y = 0.5f, z = 2.45f),
        key = resets,
    ).apply {
        (this as? CameraGestureDetector.DefaultCameraManipulator)?.isDoubleTapZoomEnabled = false
    },
    onGestureListener = rememberOnGestureListener(onDoubleTap = { _, _ -> resets++ }),
)

Parameters

orbitHomePosition

Camera's initial eye position in world space (optional). Its length is the framing distance under the default autoCenterContent = true — see above. Omitting it does not give you Filament's (0, 0, 1): SceneView's own default manipulator passes cameraNode.worldPosition, i.e. (0, 0.4, 2.75) ≈ 2.78 m for the default CameraNode. No built-in gesture returns the camera to this position either; change key to do it. A new value rebuilds the manipulator (compared by value).

targetPosition

Point in world space the camera orbits around and initially looks at (optional; defaults to the origin). Does not affect the distance. A new value rebuilds the manipulator (compared by value).

inertia

How orbit, pan and pinch coast after the finger lifts. Inertia.Default (the default) coasts like a native fling; Inertia.None stops the camera dead on release. Applied to the manipulator creator returns when it is a CameraGestureDetector.DefaultCameraManipulator. Never rebuilds it.

key

Any value, like the key of remember(key) { }: when it changes, the manipulator is rebuilt by creator at its starting pose and the camera glides back there. Use it to reset the view, or to make a new creator take effect. null (the default) never triggers a rebuild on its own.

creator

Factory for the manipulator. Override to set a custom orbit speed, etc. Called again whenever orbitHomePosition, targetPosition or key changes — not when only the lambda instance changes.

@Composable
fun rememberCameraManipulator(orbitHomePosition: Position? = null, targetPosition: Position? = null, inertia: Inertia = Inertia.Default, creator: () -> CameraGestureDetector.CameraManipulator = { createDefaultCameraManipulator(orbitHomePosition, targetPosition) }): CameraGestureDetector.CameraManipulator

rememberCameraManipulator without a key: same manipulator, same keys on orbitHomePosition and targetPosition, never rebuilt on demand. See the overload that takes key for the full documentation.

Kept visible on purpose, not only for binary compatibility. key sits before the trailing creator lambda, so without this overload a positional call such as rememberCameraManipulator(eye, target, Inertia.None, factory) would still compile but silently pass factory as the key. With it, Kotlin resolves that call (and every call that does not name key) here, where the fourth argument is the creator it always was.
