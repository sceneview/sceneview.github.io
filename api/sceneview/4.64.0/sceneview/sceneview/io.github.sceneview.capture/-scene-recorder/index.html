SceneRecorder

@Stable
class SceneRecorder

Takes shareable photos and MP4 videos of a SceneView or ARSceneView — exactly what the scene renders, AR camera feed included, and none of the Compose UI drawn over it.

Hand its surfaceMirrorer to the scene, then capture:

val recorder = rememberSceneRecorder()
val scope = rememberCoroutineScope()
ARSceneView(surfaceMirrorer = recorder.surfaceMirrorer, ...)  // or SceneView(...)

Button(onClick = { scope.launch { recorder.savePhoto() } }) { Text("Photo") }
Button(onClick = {
    if (recorder.isRecording) recorder.stopRecording() else recorder.startRecording()
}) { Text(if (recorder.isRecording) "Stop" else "Record") }

Photos

takePhoto copies the scene view's own pixels at full resolution with PixelCopy (a TextureView scene is read with TextureView.getBitmap), then draws the overlay on the copy. savePhoto does the same and writes a JPEG or PNG file.

Videos

startRecording encodes H.264 in an MP4, 1080p at 30 fps by default, in the scene view's own aspect ratio (see VideoSettings), optionally with the microphone and a maximum duration. It uses SurfaceMirrorer: the scene is rendered a second time straight into the encoder, so there is no MediaProjection consent dialog, no foreground service, and no system UI or Compose overlay in the file. The overlay is drawn on every frame on Android 10 and newer.

When a recording ends

A recording ends — its file finalised and onRecordingFinished called — on stopRecording, at VideoSettings.maxDurationMillis, on release, and as soon as the scene feeding it goes away: the SceneView / ARSceneView leaves composition or stops using surfaceMirrorer. A recorder from rememberSceneRecorder also stops its recording when the screen goes to the background (Lifecycle.Event.ON_STOP): the scene stops rendering there, and an encoder fed no frames for that long produces a frozen or unplayable video.

State

isRecording, elapsedMillis, lastRecording, lastError, overlay and onRecordingFinished are Compose state: read them in composition and the UI follows.

Threading

Call startRecording, stopRecording and release from the main thread — the mirror's Filament swap chain is destroyed there. takePhoto and savePhoto are main-safe: call them from any coroutine.

Files

Without an explicit file, captures go to the app's external files folder (Android/data/<package>/files/captures/, or the internal files folder if there is none) — no storage permission needed. Share them through a FileProvider, or copy them to MediaStore.
